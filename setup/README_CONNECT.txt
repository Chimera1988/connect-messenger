Connect — настройки новой системы (важно прочитать перед развёртыванием)

1. Сделайте резервную копию базы Supabase. НЕ запускайте SQL до резервного копирования.
2. Замените файлы проекта файлами из этого ZIP и разверните на Vercel.
3. В Vercel -> Environment Variables добавьте серверные переменные:
   SUPABASE_SERVICE_ROLE_KEY = service_role key из Supabase (НИКОГДА не NEXT_PUBLIC_)
   CONNECT_ADMIN_USER_ID = UUID вашего существующего аккаунта администратора из auth.users.
   Установите для Production, Preview при необходимости, затем redeploy.
4. Выполните setup/CONNECT_SETUP.sql в Supabase SQL Editor.
   SQL меняет FK профилей, чтобы история сообщений сохранялась после удаления Auth-аккаунта.
5. В Supabase Auth -> Providers -> Email отключите свободную регистрацию (Allow new users to sign up).
   Приглашения через admin.generateLink должны быть проверены в вашей конфигурации Auth.
6. В Supabase Auth -> URL Configuration добавьте https://connect-chat.duckdns.org в разрешённые Redirect URLs.
7. Проверьте сначала тестовым аккаунтом: приглашение, вход, создание пака, отправку стикера,
   отображение у второго участника и удаление тестового аккаунта.

Изменения в проекте: app/page.tsx, app/globals.css, два новых API-маршрута,
lib/server/admin.ts, setup/CONNECT_SETUP.sql.

ОГРАНИЧЕНИЯ:
- Личные паки видит только владелец; общие паки видят все. Установка отдельным нажатием
  пока не нужна: общие паки появляются автоматически.
- Изображения PNG/WebP/GIF до 2 МБ; загружать можно по 30 за раз.
- Ссылки-приглашения генерирует Supabase Auth. Их срок действия зависит от настроек Auth.
- При удалении аккаунта сообщения и вложения сохраняются у собеседников; профиль
  обезличивается и скрывается из контактов. Некоторые дополнительные данные из
  сторонних сервисов могут требовать отдельной очистки.
- Удаление аккаунта администратора через интерфейс заблокировано.
- Действующая конфигурация Vercel и SQL должны быть настроены перед использованием.
