# Connect Messenger — аудиозвонки для PWA (первый этап)

**Только аудио.** Никаких видеозвонков и изменений Android/APK.

### Реализовано в исходном коде

- Кнопка трубки рядом с меню «⋯» в шапке переписки.
- Исходящий звонок и входящий вызов (в **открытой** PWA).
- Принять, отклонить, отменить, завершить, выключить/включить микрофон, включить удалённый звук по касанию.
- WebRTC-шифрованная аудиопередача браузер↔браузер; Supabase хранит только сведения о вызове, SDP и ICE-кандидаты для установления соединения, **не запись разговора**.
- Записи звонков со статусами `ringing`, `active`, `ended`, `declined`, `missed`, `failed`.
- RLS: вызовы и ICE видны только двум участникам переписки, изменение состояния — только через проверяющие права SQL-функции.
- Подготовлена настройка Coturn TURN REST: секрет хранится на сервере, клиент получает временные учётные данные.

### Установка в PWA (один пакет)

1. Скопируйте в проект из архива:
   - `components/ConnectAudioCalls.tsx` (новый)
   - `app/calls.css` (новый)
   - `app/api/calls/ice/route.ts` (новый)
2. Измените **два** существующих файла. Проще всего запустить в корне проекта `python3 scripts/install_into_repo.py` (скрипт делает резервные копии и не удаляет другие изменения). Либо вручную:

   В `app/page.tsx` сразу после `'use client';` добавьте:

   ```tsx
   import ConnectAudioCalls from '../components/ConnectAudioCalls';
   ```

   Сразу **после** строки, начинающейся на `return <div className={'connect-app '`, перед условием `{!supabase ?` добавьте:

   ```tsx
   <ConnectAudioCalls client={supabase} userId={user?.id || null} conversationId={selected?.id || null} peerId={selected?.other?.id || null} peerName={currentName}/>
   ```

   В `app/layout.tsx`, после импорта `./liquid-glass.css` добавьте:

   ```tsx
   import './calls.css';
   ```

3. **SQL уже применён** в Supabase проекта `connect-messenger` (`tpwkmoxxzjfdsqsomhhr`) в рамках этой задачи, повторно запускать его не нужно. Файл `sql/connect_audio_calls.sql` приложен для контроля и резервной копии.
4. Убедитесь, что `supabase_realtime` реплицирует `connect_calls` и `connect_call_ice` (SQL добавляет обе таблицы).
5. Запустите `npm run build`, затем откройте Connect PWA на **двух разных устройствах** с разными аккаунтами. Разрешите доступ к микрофону. Откройте переписку, нажмите кнопку трубки.

### TURN (важно для мобильной сети)

По умолчанию есть публичный STUN для прямого соединения. Через сложные NAT/CGNAT без TURN соединение может **не установиться**, хотя сообщения будут работать. Для стабильного мобильного соединения нужен собственный TURN или провайдер, поддерживающий Coturn REST API. Добавьте только в **серверные переменные Vercel**:

```
CONNECT_TURN_URLS=turn:your-turn-host:3478?transport=udp,turns:your-turn-host:5349?transport=tcp
CONNECT_TURN_SHARED_SECRET=<случайный секрет, совпадающий с shared-secret Coturn>
```

Не добавляйте секрет в `NEXT_PUBLIC_` и не сохраняйте статические TURN-пароли в браузерном коде.

### Ограничения PWA (особенно iPhone)

- Пока без системного входящего звонка при **закрытом** приложении: Realtime и браузерный WebRTC не работают как полноценный нативный телефонный сервис в фоне. Фоновое поведение микрофона iOS не гарантировано.
- Нет видеосвязи. Android APK не требуется пересобирать.
- Нет групповых звонков, записи разговоров или звуковой мелодии вызова.
- Функция «Включить звук» предусмотрена из-за ограничений автозапуска аудио в Safari.
- Нужна публикация сайта по HTTPS; в приватном просмотре разрешения могут сбрасываться.

### Проверка

*Нельзя заявить, что звонки проверены между двумя телефонами, пока не подключены две PWA и TURN. Подготовлен код и проверен его синтаксис; нужна сборка проекта и реальный тест.*

При проблеме с передачей звука проверьте разрешения микрофона, WebRTC `connectionState` и TURN. Не заменяйте рабочий код мессенджера целиком: патч добавляет только компонент звонков.
